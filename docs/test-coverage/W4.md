## 背景

`lib/view_models/bookmarks/` の 4 つの ViewModel は、ブックマーク画面の並び替え・グルーピング・取り消し（undo）を担う中核ですが、テストが 1 本もありません。`reorder` は `fractional_indexing` で前後キーから新しい `orderIndex` を生成しており、境界（先頭・末尾への移動）を間違えると並び順が壊れます。`unbookmark` / `removeBookmark` が返す undo 関数も、復元漏れがあればユーザーのデータが失われます。

`lib/providers/` も `resin` と `banner_notifier` 以外はほぼ未テストです。

### PR の作成

作業ブランチに push したら、**ベースブランチ（W3 の作業ブランチ）を base にして PR を 1 本作成**してください。

- **draft にしないでください。** draft では自動レビュー（`.github/workflows/claude-code-review.yml`）が動きません。
- タイトルは `test: W4 ...` のように、どのワークストリームかがわかる形にしてください。
- 本文には次を記載してください: テストを追加した ViewModel / Provider の一覧、カバレッジの変化、飛ばした対象とその理由。
- リポジトリに PR テンプレートはありません。本文は通常どおり記述してください。
- PR 作成後、**CI（`Test & Lint`）が緑になるまで**が完了条件です。
- **bot によるレビューコメント（`.github/workflows/claude-code-review.yml` の自動レビューなど）には、ユーザーから明示的な指示があるまで対応しないでください。** 修正・返信・resolve のいずれも行わず、そのまま残してください。
- レビュー指摘でベースブランチ（W3 の作業ブランチ）が更新されたら、取り込んでからテストを再実行してください。

  ```bash
  git fetch origin && git merge origin/<W3 の作業ブランチ>
  ```

- **レビューコメントへの対応を指示されたら、修正 → 該当レビューコメントへの返信 → スレッドの resolve → push の順**で行ってください。先に push すると、どの指摘に対する変更なのかがレビュアーから追えなくなります。
- **コンフリクト解決など、内容を変更しない push の後は、コードレビューのワークフローが Actions に現れるのを待ってからキャンセルしてください。** 実質的な差分がない変更に自動レビューを走らせないためです。ワークフローは push 直後には現れないことがあるので、現れるまで待ってからキャンセルします。
- **作業完了後、その PR にサブスクライブされていないことを確認してください。** サブスクライブが残っていると、以後の PR の動きでセッションが起動し続けます。残っている場合は解除してください。

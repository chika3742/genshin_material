# W2: `lib/models/` のロジックのテスト

> テストカバレッジ改善ワークストリームの 1 つです。全体像は [README.md](./README.md) を参照してください。

## 前提

- **依存**: W0〜W1（すべてベースブランチに含まれています）。`test/utils/asset_data.dart` の拡充ヘルパを使います。
- **ベースブランチ**: W1 の作業ブランチ。作業ブランチはこのベースから切られた状態でセッションが始まります（**Claude Code Web が自動で作成するため、自分で `git checkout -b` する必要はありません**）。
- **すべての Flutter/Dart コマンドに `fvm` を前置すること**（`.fvmrc` で Flutter バージョンを固定しているため）。
- **完了したら、ベースブランチを base とした PR を 1 本作成してください。** ワークストリームごとに個別にレビューします。
- 他ワークストリームの PR にはコメント・変更を行わないでください。
- ブランチを積み上げる都合上、前のワークストリームが追加したファイルが手元に見えますが、**それらを含め、自分の担当パス以外は変更しないでください。** 各 PR の差分を自分の担当分だけに保つためです。

## 背景

`lib/models/` は freezed の生成コードが大半ですが、**手書きのファクトリ・メソッド**にはブックマークのレベル範囲算出や素材の並び順といった重要なロジックが埋まっています。特に `BookmarkGroup.fromBookmarks` はブックマーク一覧の表示レベル範囲を決める中心的な関数でありながら、テストがまったくありません。

**生成コード（`*.freezed.dart` / `*.g.dart`）そのものはテスト対象外です。** 手書きのメソッドとファクトリだけを狙ってください。

## コード規約（`CLAUDE.md` 準拠）

- 文字列は**ダブルクォート**
- 複数行の引数リストには**末尾カンマ**必須
- フィールド・ローカル変数は可能な限り `final`
- `test/` 内の相互参照は**相対 import**
- テスト名・`group` 名は日本語・英語どちらでも可。ただし**1 ファイル内では統一**する
- ロケール依存の文字列リテラルをテストに直書きしない（`LocaleSettings` の既定は `ja`）

### PR の作成

作業ブランチに push したら、**ベースブランチ（W1 の作業ブランチ）を base にして PR を 1 本作成**してください。

- **draft にしないでください。** draft では自動レビュー（`.github/workflows/claude-code-review.yml`）が動きません。
- タイトルは `test: W2 ...` のように、どのワークストリームかがわかる形にしてください。
- 本文には次を記載してください: テストを追加したメソッド・ファクトリの一覧、カバレッジの変化、飛ばした対象とその理由。
- リポジトリに PR テンプレートはありません。本文は通常どおり記述してください。
- PR 作成後、**CI（`Test & Lint`）が緑になることと、自動レビューの指摘に対応することまで**が完了条件です。
- レビュー指摘でベースブランチ（W1 の作業ブランチ）が更新されたら、取り込んでからテストを再実行してください。

  ```bash
  git fetch origin && git merge origin/<W1 の作業ブランチ>
  ```

## 報告事項

1. **作成した PR の URL**
2. 追加したテストファイルと、追加したテストケース数
3. `./scripts/coverage.sh` の値（W0 のベースラインとの差分。可能なら `lib/models/` 配下の数値）
4. **テスト不能と判断して飛ばした対象と、その理由**
5. 作業中に見つかったプロダクションコードの不具合・疑わしい挙動（あれば）。特に `BookmarkGroup.fromBookmarks` は `assetData.characters[...]!` / `assetData.weapons[...]!` で強制アンラップしているため、アセット更新で ID が消えたときの挙動に問題があれば報告すること

## 背景

`lib/components/` には 40 以上の再利用コンポーネントがありますが、widget テストがあるのは `furnishing_table` / `style_parsed_text` / `release_note_contents` / `release_notes_timeline` の 4 つだけです。特に `custom_range_slider.dart` は「Flutter 標準の `RangeSlider` が thumb 以外のタッチに反応しない」問題を回避するために独自のジェスチャ処理を書いており、リグレッションが起きやすい割に検証手段がありません。

**ページ全体のテストは今回の対象外です。** 単体で pump できるコンポーネントに限定してください。

## 進め方の注意

- **画像を読む可能性のあるコンポーネントは `shouldHideImagesProvider.overrideWithValue(true)` を既定にしてください。** ネットワークやファイル I/O がテスト内で走るのを避けるためです（`material_item_test.dart` の「画像を出さないこと」の検証だけは例外的に両方の値を試す）。
- **文言の検証にロケール依存の文字列リテラルを直書きしないでください。** `LocaleSettings` の既定は `ja` です。テキストの存在を確認したい場合は `tr.*` の参照を使うか、`find.byType` / `find.byKey` で構造を検証してください。
- **単体で pump できないコンポーネントに当たったら、そのコンポーネントは飛ばして次に進んでください。** `AssetData` 全体や GoRouter のコンテキストを要求するものを、無理にページごと組み立てないでください。飛ばした対象と理由は最終報告に列挙します。
- ジェスチャのテストには `tester.drag` / `tester.timedDrag` / `TestGesture` を使い、`await tester.pumpAndSettle()` で安定させてください。

## コード規約（`CLAUDE.md` 準拠）

- 文字列は**ダブルクォート**
- 複数行の引数リストには**末尾カンマ**必須
- フィールド・ローカル変数は可能な限り `final`
- `test/` 内の相互参照は**相対 import**
- `void` を async 関数の戻り値型にしない（`Future<void>` を使う）
- テスト名・`group` 名は日本語・英語どちらでも可。ただし**1 ファイル内では統一**する
- `PageController` などの `dispose` が必要なオブジェクトは `tearDown` で確実に破棄する（`test/widget/bookmark_furnishing_sets_tab_test.dart` 参照）

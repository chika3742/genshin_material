> テストカバレッジ改善ワークストリームの 1 つです。全体像は [README.md](./README.md) を参照してください。

## 前提

- **依存**: W0〜W5（すべてベースブランチに含まれています）。
- **ベースブランチ**: W5 の作業ブランチ。作業ブランチはこのベースから切られた状態でセッションが始まります（**Claude Code Web が自動で作成するため、自分で `git checkout -b` する必要はありません**）。
- **すべての Flutter/Dart コマンドに `fvm` を前置すること**（`.fvmrc` で Flutter バージョンを固定しているため）。
- **ファイルの作成・編集には Edit / Write ツールを使い、シェルの heredoc（`cat > file <<EOF`）は可能な限り使わないでください。** heredoc は Edit / Write で正しく書き込めない場合のみのフォールバックとします。
- **完了したら、ベースブランチを base とした PR を 1 本作成してください。** ワークストリームごとに個別にレビューします。
- 他ワークストリームの PR にはコメント・変更を行わないでください。
- **W6 は唯一 `lib/` 本体を広く変更するワークストリームです。** チェーンの最後に位置するため W0〜W5 の成果はすべてベースブランチに入っていますが、リファクタが既存テストに影響しないことを `fvm flutter test` で必ず確認してください。

## 背景

`lib/core/hoyolab_api.dart` はコンストラクタの中で `FirebaseRemoteConfig.instance.getBool(...)` を呼んでおり、Firebase を初期化しないとインスタンス化すらできません。355 行あるこのファイルには DS トークン生成やエラーハンドリングといった検証したいロジックが詰まっているのに、テストが 1 本も書けない状態です。同じ問題が `lib/core/asset_updater.dart` にもあります。

一方でリポジトリには既に **`RemoteConfigRepository`（`lib/data/repositories/remote_config_repository.dart`）と `remoteConfigProvider`、型付きキー `RemoteConfigKeys`（`lib/core/remote_config_keys.dart`）、テスト用スタブ `stubRemoteConfig()`（`test/utils/stub_remote_config.dart`）が揃っています。** 新しい抽象を作る必要はなく、**直接参照している側をこれらに置き換えるだけ**です。

このワークストリームは ①その注入リファクタ ②リファクタで書けるようになる `lib/core/` のテスト の 2 つを担当します。

## 作業一覧（1）: Remote Config への直接依存の除去

現在 `FirebaseRemoteConfig.instance` を直接参照しているのは以下です。

```
lib/providers/hoyolab_credential.dart:62
lib/main.dart:72
lib/core/asset_updater.dart:59

lib/pages/database/characters/character_list.dart:130, 239
lib/pages/tools/resin_calc.dart:120
```

これを次のように置き換えてください。

| ファイル | 変更内容 |
|---|---|
| `lib/core/hoyolab_api.dart` | コンストラクタで `FirebaseRemoteConfig.instance` を読む代わりに、**必須引数 `RemoteConfigRepository remoteConfig` を受け取る**。ガード（`hoyolabLinkEnabled` が false なら `StateError`）はそのまま維持する |
| `lib/core/asset_updater.dart` | 同様に注入する。**このクラスは既に `httpClient` を任意注入できる設計**なので、同じ流儀に合わせること |
| `lib/providers/hoyolab_credential.dart` | `ref.read(remoteConfigProvider)` 経由に置き換え |
| `lib/pages/database/characters/character_list.dart` | `ref.watch(remoteConfigProvider).get(RemoteConfigKeys.hoyolabLinkEnabled)` に置き換え（2 箇所） |
| `lib/pages/tools/resin_calc.dart` | 同上（1 箇所） |
| `lib/main.dart` ほか | `HoyolabApi(...)` / `AssetUpdater(...)` の生成箇所を追随修正。`main.dart` の Firebase 初期化そのものは残してよい |

移行が完了すると、旧来の文字列定数クラス `lib/constants/remote_config_key.dart` は参照ゼロになるはずです。**参照ゼロを確認した上で削除し、`lib/core/remote_config_keys.dart` の `RemoteConfigKeys` に一本化してください。** 参照が残る場合は削除せず、残った箇所を報告してください。

### 互換性の注意

- `AssetUpdater` は `test/unit/asset_updater_test.dart` がコンストラクタを直接呼んでいます。**シグネチャ変更に合わせてこの既存テストも更新してください**（`dataSchemaVersion` を渡している経路は維持すること）。
- `HoyolabApi.queue`（`static final ApiRequestQueue`）はインスタンスをまたいで共有される static です。リファクタでこの性質を変えないでください。
- リファクタは**振る舞いを変えないこと**が目的です。ガード条件やデフォルト値を変えないでください。

### PR の作成

作業ブランチに push したら、**ベースブランチ（W5 の作業ブランチ）を base にして PR を 1 本作成**してください。

- **draft にしないでください。** draft では自動レビュー（`.github/workflows/claude-code-review.yml`）が動きません。
- タイトルは `test: W6 ...` のように、どのワークストリームかがわかる形にしてください。
- 本文には次を記載してください: リファクタの内容と影響範囲、テストを追加した対象の一覧、カバレッジの変化、**リファクタ後に新たにテスト可能になったもの**（特に `lib/providers/game_data_sync.dart`）。
- リポジトリに PR テンプレートはありません。本文は通常どおり記述してください。
- PR 作成後、**CI（`Test & Lint`）が緑になるまで**が完了条件です。
- **bot によるレビューコメント（`.github/workflows/claude-code-review.yml` の自動レビューなど）には、ユーザーから明示的な指示があるまで対応しないでください。** 修正・返信・resolve のいずれも行わず、そのまま残してください。
- レビュー指摘でベースブランチ（W5 の作業ブランチ）が更新されたら、取り込んでからテストを再実行してください。

  ```bash
  git fetch origin && git merge origin/<W5 の作業ブランチ>
  ```

- **レビューコメントへの対応を指示されたら、修正 → 該当レビューコメントへの返信 → スレッドの resolve → push の順**で行ってください。先に push すると、どの指摘に対する変更なのかがレビュアーから追えなくなります。
- **コンフリクト解決など、内容を変更しない push の後は、コードレビューのワークフローが Actions に現れるのを待ってからキャンセルしてください。** 実質的な差分がない変更に自動レビューを走らせないためです。ワークフローは push 直後には現れないことがあるので、現れるまで待ってからキャンセルします。
- **作業完了後、その PR にサブスクライブされていないことを確認してください。** サブスクライブが残っていると、以後の PR の動きでセッションが起動し続けます。残っている場合は解除してください。
